## `platform-spend-reconcile`

An account-spend record in the agent tree (`<prefix>/agents/<publisher>/<host>/account/<account>`) is one publisher's own estimate, summed from the cost its harness reported for each turn. Nothing compares the total with what the Claude Platform billed: a turn killed before it reported a cost, a tool that spends the key without publishing, and the harness's own estimation error all stay uncorrected until an operator reads the Platform console and corrects one publisher's level by hand (in `ccc`, `ccc budget set NAME --spent USD`). An automatic reconcile would poll the Platform's spend-reporting API with an admin credential and publish the correction. It belongs in this daemon, which already owns a poller with a request budget, not in a one-shot CLI. To settle before it can be built: which Platform endpoint, and how stale its figures are; where the admin credential lives; and how the correction appears in the tree — a record under a publisher name of the daemon's own, or a new topic — without breaking the rule that a publisher writes only its own subtree. Done when the total spend of an API-key account converges on the Platform's figure with no manual step. Code site: the tree-ownership comment above the daemon's subscriptions in `crates/claude-usage-mqtt/src/daemon.rs`.

## `agent-tree-second-publisher-and-reader`

The agent tree (README, "The agent tree") is specified as a wire contract any tool can implement, with these crates as one implementation of it. So far `ccc` is its only publisher, through `AgentClient`, and the only thing read back is account spend (`fetch_accounts`): nothing publishes into the tree without these crates, and nothing reads `session/` or `ended`. Until both exist the contract is unproven against a second implementation — that the README alone is enough to write a publisher for a tool that cannot link these crates (one with its own MQTT client, or a WASM guest), that the generic session fields mean the same thing coming from a second harness, and that a dashboard can show every agent from the three filters. Done when (1) a publisher that does not use `AgentClient` publishes sessions and account spend which `claude-usage-mqtt-core` decodes and whose spend the combining rules total correctly beside `ccc`'s, and (2) a session reader exists, in `claude-usage-mqtt-client` or in a dashboard, that follows `session/` and `ended` from more than one publisher; and the README is corrected wherever either had to guess. Code site: the module doc of `crates/claude-usage-mqtt-client/src/agents.rs`.
